# Nivora Subscription Platform

پایه بک‌اند فروش اشتراک با پلن‌های قابل‌ویرایش و پرداخت کارت‌به‌کارت.

## امکانات نسخه فعلی

- افزودن و ویرایش پلن، قیمت، حجم، مدت، تعداد دستگاه و ترتیب نمایش
- فعال/غیرفعال کردن پلن بدون حذف سوابق
- ثبت سفارش و اطلاعات رسید کارت‌به‌کارت
- صف بررسی دستی و تأیید/رد مدیر
- ساخت اشتراک در وضعیت `pending_provision` پس از تأیید
- ثبت رخدادهای مدیریتی برای حسابرسی
- محل آماده برای اتصال provisioner پنل 3X-UI و ایجنت بررسی رسید
- مدیریت همکاران فروش، وضعیت فعال/مسدود و تخفیف پیش‌فرض
- کیف پول دفترکلی با شارژ، برداشت و ریزتراکنش غیرقابل‌حذف
- قیمت اختصاصی هر پلن برای هر همکار
- داشبورد کامل همکار با دفترچه مشتریان اختصاصی، جست‌وجو و پرونده هر مشتری
- ساخت و تمدید اشتراک از داخل پرونده مشتری، ثبت مبلغ فروش و محاسبه سود
- مدل چند لوکیشن، ارائه‌دهنده و ظرفیت سرور
- مسیر هوشمند مستقیم و Cloudflare Clean IP برای هر لوکیشن، تست سلامت و خروجی اشتراک چندمسیره
- اپ اختصاصی اندروید با دو نقش مشتری و همکار؛ اتصال واقعی، فروش، کیف پول، تمدید، اعلان و پشتیبانی

## اتصال 3X-UI

اتصال با API Token اختصاصی انجام می‌شود. تنظیمات لازم در `.env` قرار می‌گیرند:

- `PANEL_BASE_URL`: آدرس پنل تا قبل از `/panel/api`
- `PANEL_API_TOKEN`: توکن اختصاصی سرویس فروش
- `PANEL_INBOUND_ID`: شناسه inbound مقصد
- `PANEL_SUBSCRIPTION_BASE_URL`: ابتدای لینک عمومی اشتراک
- `PUBLIC_BASE_URL`: دامنه عمومی Nivora برای لینک اشتراک پایدار، مثل `https://b.nivorali.com`
- `PANEL_TLS_REJECT_UNAUTHORIZED`: در استقرار نهایی باید `true` باشد؛ مقدار `false` فقط برای گواهی فعلی مبتنی بر IP است.

### مسیرهای Cloudflare Clean IP

مدل Clean IP با Reality فرق دارد. در هر لوکیشن یک inbound مستقیم Reality و یک inbound جداگانه VLESS روی WebSocket یا gRPC با TLS تعریف کنید. رکورد ساب‌دامین CDN باید در Cloudflare **Proxied (ابر نارنجی)** باشد. سپس در «لوکیشن‌ها ← مسیرها»، Clean IPها را از فهرست خام قابل اعتماد وارد کنید و همان ساب‌دامین نارنجی را به‌عنوان SNI/Host ثبت کنید.

Nivora یک هویت مشتری را به هر دو inbound متصل می‌کند. بنابراین مشتری با یک لینک اشتراک، هم مسیر مستقیم Reality و هم نسخه‌های Clean IP مسیر CDN را دریافت می‌کند و اپ Nivora روی شبکه همان مشتری سالم‌ترین مسیر را انتخاب می‌کند. Clean IP نشان‌دهنده کشور ثابت نیست؛ فقط یک مسیر لبه Cloudflare است و باید به‌صورت دوره‌ای تست و به‌روزرسانی شود.

با تأیید سفارش، کلاینت روی inbound تعیین‌شده ساخته می‌شود، حجم پلن به بایت تبدیل می‌شود، اعتبار به‌صورت «شروع پس از اولین استفاده» ثبت می‌شود و لینک اشتراک در سفارش ذخیره می‌گردد.

## اجرا

1. فایل `.env.example` را مبنای متغیرهای محیطی قرار دهید.
2. مقدار `ADMIN_TOKEN` را حتماً با یک رشته طولانی و تصادفی عوض کنید.
3. اجرا: `node src/server.js`
4. تست: `npm.cmd test`

پس از اجرا، پنل فارسی در `http://127.0.0.1:8787/admin` در دسترس است. برای ورود، همان مقدار `ADMIN_TOKEN` را وارد کنید. مقدار پیش‌فرض فقط برای توسعه محلی است و نباید روی سرور استفاده شود.

فروشگاه مشتری در `http://127.0.0.1:8787/` باز می‌شود. کارت‌های پرداخت از بخش «کارت‌های بانکی» پنل مدیریت قابل افزودن، ویرایش، مرتب‌سازی و فعال/غیرفعال‌کردن هستند. مشتری پس از ثبت رسید یک کد خصوصی دریافت می‌کند که برای پیگیری وضعیت و دریافت لینک اشتراک لازم است.

مرکز همکاری در `http://127.0.0.1:8787/reseller` قرار دارد. هر همکار فقط دفترچه، مشتریان، فروش‌ها و تراکنش‌های خودش را مشاهده می‌کند. ساخت سرویس از کیف پول همکاری کسر و مبلغ فروش به مشتری برای گزارش سود ثبت می‌شود.

سرویس عمداً فقط روی `127.0.0.1` باز می‌شود تا پیش از افزودن HTTPS و احراز هویت عمومی در اینترنت منتشر نشود.

## ایجنت تأیید خودکار رسید (Auto-review)

ایجنت وقتی مشتری واریز کارت‌به‌کارت می‌کند و رسید/شناسه می‌فرستد، به‌طور خودکار سفارش را تأیید، رد یا برای بررسی دستی نگه می‌دارد. مبنای تأیید **پیامک واقعی بانک** است، نه صرفاً عکس رسید (عکس جعل‌شدنی است).

### اجزا
- `src/bank-sms.js` — پارس پیامک واریز بانکی به مبلغ (ریال)، شماره پیگیری، چهار رقم آخر کارت و جهت تراکنش؛ با نرمال‌سازی ارقام فارسی/عربی.
- `src/receipt-ocr.js` — OCR کمکی و آفلاین با `tesseract` (fas+eng) برای خواندن شماره پیگیری/مبلغ از عکس. فقط مکمل است، نه مبنای تأیید.
- `src/auto-review.js` — موتور تصمیم محافظه‌کارانه و جاروی دوره‌ای.

### جریان کار
1. یک اپ **SMS-Forwarder** روی گوشیِ حاوی سیم‌کارتِ حسابِ مقصد، پیامک واریز را به `POST /api/sms/ingest` می‌فرستد (با هدر `x-webhook-secret`).
2. پیامک پارس و در جدول `bank_transactions` ذخیره می‌شود.
3. ایجنت سفارش‌های `under_review` را با واریزهای واقعی تطبیق می‌دهد:
   - **تأیید خودکار** وقتی شماره پیگیری و مبلغ منطبق باشند، یا دقیقاً یک واریز هم‌مبلغ در بازه‌ی زمانی باشد.
   - **رد خودکار** وقتی شماره پیگیری قبلاً برای سفارش دیگری مصرف شده باشد (ضد استفاده‌ی مجدد).
   - **بررسی دستی** در حالت‌های مبهم (چند واریز هم‌مبلغ) یا نبود واریز متناظر؛ سفارش دست‌نخورده می‌ماند.
4. هر واریز فقط یک‌بار مصرف می‌شود و هر تصمیم با امتیاز اطمینان و دلیل در `order_reviews` و `audit_log` ثبت می‌شود.

### API
- `POST /api/sms/ingest` — وبهوک دریافت پیامک (راز مشترک، نه توکن مدیر). بدنه: `{ message, receivedAt?, sender? }`.
- `GET /api/admin/bank-transactions?status=` — فهرست واریزهای دریافتی.
- `POST /api/admin/orders/:id/auto-review` — اجرای دستی ایجنت روی یک سفارش.
- `GET /api/admin/orders/:id/reviews` — تاریخچه‌ی تصمیم‌های ایجنت.

### راه‌اندازی
۱. متغیرهای `SMS_WEBHOOK_SECRET` و `AUTO_REVIEW_*` را در `.env` تنظیم کنید.
۲. برای OCR: `apt install tesseract-ocr tesseract-ocr-fas` و `RECEIPT_OCR_ENABLED=true`.
۳. یک اپ SMS-Forwarder (مثل «SMS to URL/Webhook») روی گوشیِ سیم‌کارت مقصد نصب کنید و آن را به `https://<دامنه>/api/sms/ingest` با هدر `x-webhook-secret` وصل کنید.

## اپ اندروید

نسخه‌های APK هر انتشار در بخش Releases مخزن ساخته می‌شوند. برای اکثر گوشی‌های جدید فایل `arm64` مناسب است. راهنمای فنی و ساخت محلی در [`android/README.md`](android/README.md) قرار دارد.

### پیامک بازیابی رمز

بازیابی رمز با کد یک‌بارمصرف ۶ رقمی و اعتبار ۱۰ دقیقه انجام می‌شود. وبهوک پیامکی باید در `.env` با `SMS_PROVIDER_URL` تنظیم شود و JSON شامل `to`، `message` و `sender` را بپذیرد. توکن اختیاری با `SMS_PROVIDER_TOKEN` در هدر Bearer ارسال می‌شود. گزینه `PASSWORD_RESET_DEBUG_CODE=true` فقط برای توسعه محلی است و نباید روی سرور اصلی فعال باشد.
